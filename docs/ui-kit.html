Layout

SectionBlock

The standard page-section wrapper. Every section on every page uses it — never hand-roll a heading. Titles are sentence case (“Recent transactions”, not “Recent Transactions”).

<SectionBlock title="Recent transactions" subtitle="Last 30 days"

SectionTitle · Spacer · ListStack

SectionTitle is the header SectionBlock renders internally — use it directly only when you need the header without the block. Spacer is vertical space (size in px). ListStack is a simple vertical stack for rows.

ProgressBar

ProgressBar

A single completion track. Pass value/max rather than a percentage, so the component can render both the bar and a “16 of 39” label from one source. Overpayment is real, so value is clamped for the bar while the label keeps your true figures.

16 of 39 EMIs paid 41%
₹1,67,200 of ₹3,24,500 repaid52%
Fully repaid100%
PropTypeNotes
value *numberClamped into 0..max for the bar.
max *number<= 0 renders an empty track, never NaN.
toneUiToneColours the fill only; the track stays neutral.
labelstringAlso becomes the aria-label.
showPctbooleanRounded percentage on the right.
Usage
<ProgressBar value={paidEmis} max={tenureMonths} tone="red"
             label={`${paidEmis} of ${tenureMonths} EMIs paid`} showPct />

Inputs & filters

FormField

Wraps any input with its label. The label is always above the field — never placeholder-only. Mark required fields with * in the label text.

Modals

ModalShell + ModalActions

The only sanctioned modal. Backdrop-click closing is ModalShell’s job — do not override it, and never use the browser <dialog> or a custom overlay div. Put the destructive action in ModalActions.leading.

Add repayment
PropTypeNotes
ModalShell: title, onClose, footer, children.
ModalActions: primaryLabel, secondaryLabel (default “Cancel”), onPrimary, onSecondary, leading, destructive, disabled, hidePrimary.
Put a hidden submit button inside a real <form onSubmit> so Enter submits — see the gold page. Several pages still submit from onPrimary alone, which the UI-patterns skill disallows.

ConfirmDialog

Every destructive action must go through this. The confirmation names the item (“Delete "HDFC Savings"?”), never a bare “Are you sure?”, and the trigger is an outline button — never filled primary.

Currently used by zero app files. The loans and lending pages instead arm a boolean and relabel the same button to “Confirm delete?” — two clicks, no item name, no “cannot be undone”. Prefer this component in new code.
Usage
<ConfirmDialog
  title={`Delete "${item.name}"?`}
  description="This action cannot be undone."
  onConfirm={() => handleDelete(item.id)}
>
  <button className="btn-outline-danger">Delete</button>
</ConfirmDialog>

Feedback

InfoCallout · callout tones · LoadingState · ErrorScreen

InfoCallout is the title + body form. The single-paragraph form (ui-kit-callout ui-tone-amber|red) is for notes and errors inside a modal — a page-level error banner renders behind an open modal, so validation failures need the in-modal form to be visible at all.

Charts

RightLegendDonut · MiniBarChart

Both are plain inline SVG — the repo deliberately has no charting library. Colours come from the caller. When you show a centre total, compute it from the same rows as the KPI above it, or the two will disagree.

PropTypeNotes
items *{ label, value, color }[]Donut slices.
compactboolean118px instead of 150px.
showCenter, centerLabel, centerValue—The hole content.
showPct, showLegend, legendPosition—'right' | 'bottom'.
valueFormatter(n) => stringDefaults to en-IN integers.
MiniBarChart — points: { label, primary, secondary? }[], plus primaryLabel, secondaryLabel, colours, height, valueFormatter. Best for 6–12 points.

Buttons & navigation

Buttons

FabButton — one floating action button per page, fixed above the bottom nav, always opens a modal and never navigates. Use the component rather than an inline style object.

Nav · BottomNav · TabBar · InternalTabBar

Nav is the fintracker app shell (drawer + org-driven menu); vault and staff use SimpleAppNav. BottomNav is the shared bottom tab bar — several pages still hand-roll <nav className="bottom-nav"> instead of using it.

Admin app — separate system

packages/apps/admin uses its own classes: ui-kit-section, admin-card-list/admin-card-item, .admin-modal-wrap > .modal-shell, and admin-btn/admin-btn-danger. Do not use TransactionCard or KpiCard inside admin pages, and do not introduce new colour tokens there.
